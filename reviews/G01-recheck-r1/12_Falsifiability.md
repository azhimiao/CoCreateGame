# G01 可证伪假设与停止条件

全部阈值、样本、预算、时长为 **HYPOTHESIS**，是拟定决策规则，不是行业成功标准或真人测试结果。真实测试参与者=0、真实盲测/留存/收入均UNKNOWN。本轮离线模型通过只支持“规定规则下这些关可解”。

## 逐项假设与反例

| 假设 | 怎样可能是错的 | 预注册证伪/修订线 |
|---|---|---|
| H-G01-01 基础扫掠可被理解 | 玩家只看箭头前方，弯尾撞挡被认为bug | 首分钟无口头辅导，≥4/24玩家持续误解整条平移则MAJOR修订；不能靠削弱碰撞偷偷修复 |
| H-G01-02 信号门增加规划感 | 玩家认为门无因关闭、宁愿盲点开关 | RELAY中≥4/6玩家首次遇门后无法复述“离港后翻门”，或可解释规划选择没有超过BASE，先Revise；第二次仍如此停RELAY |
| H-G01-03 船期产生可读的未来选择 | 同向二选一像猜谜、船期只是限制自由 | MANIFEST中≥4/6玩家在L13式任务被困且无法指出原因，或体验明确低于BASE，修订/移除MANIFEST |
| H-G01-04 组合值得额外复杂度 | 两规则叠加后注意负担抵消乐趣 | COMBINED任务完成率/理解都低于两个单变体，且≥4/6报告混乱，则停止组合，不能因为20关已有数据强推 |
| H-G01-05 小棋盘移动端足够可读 | 触区扩展选择条频繁弹出或选错 | 记录输入中≥10%进入冲突选择条、或误触>5%（排除规则错），优先改布局/缩内容；两轮无改善停移动版 |
| H-G01-06 可撤销死锁是正向规划 | 玩家因合法却死路感到被欺骗 | ≥4/24因该原因退出/明确拒绝再玩，修订反馈/关序；第二轮未改善移除该机制/停止项目 |
| H-G01-07 原创性足以跨越克隆审查 | 仅基础轮廓+门装饰，决策没有新意 | 独立审查无法指出至少两项可测决策差异，或渠道因实质同质化拒绝且无法合理修正，Revise/Kill |
| H-G01-08 工具路线满足渠道 | 包体、旧浏览器、原生SDK卡住 | 任一硬要求实测不满足且无认可例外，停止对应渠道；不得把未测试写通过 |
| H-G01-09 资产可商业化且回款覆盖成本 | 无流量、权利过度转让、低净回款 | 11合同底线不满足/双预算触顶/维护贡献为负，停止增量，不捏造开发者净收入 |

阈值用于早期可用性筛查，6人组没有足够统计功效证明市场优越。样本不足必须报告区间和个体观察，不把2/3等小比率称显著。阈值若在看结果后改变，需标探索性并另轮复验。

## 两个独立变体的实验设计

版本：V0=BASE；V1=RELAY（无船期）；V2=MANIFEST（无门）；V3=COMBINED。都是G01实验版本，不新增游戏候选ID。V1关门因果与V2出港顺序是独立开关，不能把艺术皮肤变化当消融。将V1/2分别与V0比较，V3仅评交互负担，不预设胜者。

首轮计划24位16+玩家，每版本6人，优先相近逻辑游戏经验分层随机；非儿童定向招募。每人只测一个版本，避免记答案的携带效应。先给2个不参与统计的基础操作练习，再测6张匹配空间布局，任务顺序拉丁方平衡。来源布局冻结为L08、L09、L10、L13、L17、L18：关闭门时移除所有gates/toggles，关闭船期时manifest=[]；新增机制版本的门/船期必须由关卡作者明确配置并离线复验，不允许现场随机生成或回填同一题。

注意部分来源没有门或船期：只能作为空间母版，不得直接声称四版本已匹配。本包尚未生产正式实验配对关卡，T10前需冻结24个实验数据与逐关解/等效长度，审查干扰变量后登记hash。**这是真人试验准备的MAJOR待项，不是当前20关规则未知。** 各版本同布局与箭条数，但机关处理引起的难度差异是实验因素，不能谎称难度完全相同。

指标：无提示首30秒首次合法输入；第一分钟主动退出与原因；前5分钟合法/非法输入、误触、提示、撤销、完成局数；结束后让玩家复述规则、解释一次选择、给清晰度/挫败/愿再玩1—5评分。记录原始分母与设备、首次经验、广告=无。5分钟只是统一实验窗口，不是保证玩到哪关。研究者不解释下一步，不诱导“你觉得门创新吗”。

测试同意与匿名原始数据离线保存，P04/P01发布包不嵌研究回传；不收真实姓名或设备指纹。退出可不说明理由，缺失数据不补造。30秒与5分钟的对标观察仍UNKNOWN，不能从本项目试验反推原作。

若首轮支持可用性，只能决定是否扩展样本，不能得出留存或收益结论。D1/D7需要真实同渠道获客队列与返回事件分母，本轮没有。P02/P04/P05分别分析，禁止拿别家的留存/转化阈值套成本渠道通过率。

## 预先规定的决策顺序

1. 任一核心规则矛盾、无解内容、越界写入、侵权来源或未授权开发：BLOCKER，先停。
2. 独立审计结果由主控写`reviews/G01-audit.md`；作者只按Findings修订，不自签READY。
3. 两个变体若只有一个通过，保留单变体并重排20关，删除而非保留失败机制；数据、教程、资产、schema一并改版，重新审计。
4. 两变体均失败且基础没有足以区分的产品价值，建议G01 KILLED；不借助换美术绕开结论。
5. 可用性通过而渠道/合同失败，停相应渠道；项目是否继续由剩余实际证据和成本决定，不能把技术成功当商业成功。
