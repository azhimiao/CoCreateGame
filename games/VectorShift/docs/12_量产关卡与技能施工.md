# 120关发行候选施工与逆向审查

2026-10-22。用户授权将当前独立游戏扩展至足量关卡、渐进难度和清除技能。只实施Vector Shift，不启动G01—G10其他游戏，不执行平台投稿。

## 冻结施工合同

- 默认进入120关旅程，10章×12关。旧五张品质样盘通过独立图案试赏入口保留，原52关相位挑战保留。
- 新关卡全部离线生成，有固定种子与完整无技能解；按旋转/镜像/头尾归一化排除几何重复。保存独立审计指标，构建时校验，浏览器内不搜索生成。
- 每章平均主体数、路径追踪量和依赖复杂度逐步提高，章内包含缓和关。第一章4～10条蛇，最终章节约48～56条；盘面尺寸和缩放协同控制密度。该难度排序是HYPOTHESIS，玩家时长/误触率未知。
- 首次只解锁第一关，胜利后解锁下一关，重玩不回收已有章节。逐关保存，合法旧样盘进度继续保留；损坏存档安全回退。
- 剪刀第6关开放，每局一次，无付费/广告依赖。进入选取模式后点静止蛇，再确认原地消除；取消不消耗，误点不立即生效。所有在途动作结束前不能使用剪刀，防止并行历史顺序含糊。
- 剪刀为独立规则动作cut，允许消除受阻蛇；消耗写入严格历史。undo恢复消耗，reset恢复每局额度。正常remove仍必须检查完整射线；每关必须不依赖技能也能解完。
- 消除动效约360ms，整条蛇原地缩淡与细小光点，保留占位直到完全消失；不沿受阻方向滑出。减少动态立即结算。
- 评分：完成1星；无剪刀2星；无剪刀且无提示/失误3星。最佳记录先比较星数，再比较完成时间。提示/撤销无限，未增加生命和经济系统。
- 章节选择只渲染当前章节12项，不一次绘制120个高成本缩略图。小屏主面板保留棋盘，提示/剪刀/撤销为同一组工具，缩放移到棋盘角落。
- 导出中文离线试玩、英文Coolmath/CrazyGames候选包及版权/测试记录。平台规则须在投稿时重新核验，平台审核、玩家留存和真机性能保持未验证。

## 编码前逆向审查

| 级别 | 模糊或风险 | 施工决策 |
| --- | --- | --- |
| BLOCKER | 清除受阻蛇若仍滑行会再次穿模 | cut使用原地消失；占位到结束；无并行动作时启动 |
| BLOCKER | 存档若只允许合法remove，技能记录无法恢复 | 规则快照增加仅技能关启用的cuts计数；逐帧校验预算和恰好一次cut变化；无技能旧关保持原schema |
| BLOCKER | 量产可能产生无解或镜像重复盘 | 每关独立坐标审计、全部无技能见证重放、旋转镜像归一化去重，失败阻断生成 |
| MAJOR | 120关选择器渲染过重 | 只展示一个章节的12关，切章按需绘制 |
| MAJOR | 关卡变多不等于难度提升 | 分章约束+实测指标分布，保留缓和关并明确玩家难度未验证 |
| MAJOR | 动画结束后的通关/技能/撤销竞态 | 统一settle提交；运动中禁用技能；通关在所有主体消失后触发 |
| MINOR | 教学和过多工具挤占棋盘 | 首关文案引导，第6关单次技能引导；缩放为棋盘角工具 |

上述阻断项已有明确实现合同，允许按本稿编码；完成后逐条复验。发布状态为发行候选，不自动写成平台已上线。

长序列测试中补修：换盘/退出主动释放Canvas位图；运动纹理按需创建并在离场后释放；触摸按钮打开模态框后的同一次原生兼容点击不再关闭新弹窗。技能动作保持严格存档历史，旧无技能存档不引入新字段；旧版五盘有效存档仍留在原模式。

证据：`artifacts/campaign/browser-report.json`、`release-audit.json`、`journey-playthrough.webm`、`board-012/060/108/120.png`。录像是真实指针完成第1～6关及剪刀/撤销，不是生成视频；默认运动与减少动态覆盖范围分别记录，未将两者混同。初次长序列运行未完成的记录不作为PASS证据，报告来自修复后的完整通过运行。

## 构建与发行候选

中文试玩ZIP和Coolmath/CrazyGames候选ZIP由`src/package_delivery.py`生成并逐文件校验哈希。渠道HTML约1.58MB，含离线关卡数据；两页均需交付。Coolmath无外部网络资源；CrazyGames使用官方v3 SDK地址，init→gameplayStart只用本地mock验过。2026-10-22重新访问[CrazyGames技术要求](https://docs.crazygames.com/requirements/technical/)与[Coolmath开发者页](https://developers.coolmathgames.com/)，后者明确平台有意向后需其简单SDK，仍待平台资料与对接。

`src/build.py`会先独立重算几何、见证、唯一性、关号、技能引入、工作量和缓和关；伪造工作量、错误ID及损坏见证三个负例均被拒绝。打包时再次核对当前HTML与`release-audit.json`的SHA256，`delivery/RELEASE_MANIFEST.json`记录三个ZIP及所有构建的字节数/哈希/包内文件，便于下一次交付复核。

当前结论：内容和核心游玩循环可打包交付。真实玩家难度校准、物理手机/浏览器覆盖、名称检索、平台SDK实环境与审核尚未验证，不能写成已上线。下一批内容沿现有固定种子生成→去重→独立验解→排序→浏览器回放→截图抽审→打包流程推进。
