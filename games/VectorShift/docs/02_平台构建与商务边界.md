# 02｜平台构建、准入和 IP 合同检查

本节是**研发准备清单**，不是已获得平台资质的证明。官网政策有时间变化，实际提交前须以最新要求和合同为准。

## Coolmath Games（优先测试非独家授权）

官方投稿：https://www.coolmathgames.com/submit-a-game

- 适合逻辑/规划/解谜。必须符合家庭友好定位；无开发者广告、无外链、无回传统计数据等要求。
- 构建候选：`dist/coolmath/index.html`：不进行试玩日志记录，也不展示导出事件按钮；无需网络。
- **未核验事项**：具体当前标题/画面要求、横竖屏偏好、源码交付、每次授权定价、许可期限、商业条款、是否接受本作机制。
- 拿到真实录屏/玩家数据后再提交；如果询盘，可以发送普通 demo 截图、短视频与无广告构建。

## CrazyGames（优先验证玩家数据，而非一开始谈采购）

开发者入口：https://developer.crazygames.com/

- Basic Launch 用于真实小流量测试，能否晋级取决于平台规则与玩家数据。
- `dist/crazygames-basic/index.html` 不含广告；不能称已完成 Full Launch SDK 集成。
- **未核验事项**：当前尺寸限制、广告 SDK 的确切接入、广告位/节奏、移动端性能基准、QA 审核、未来交叉发行是否冲突。
- 关键策略：把平台进来的流量、游玩漏斗和成本分开统计。

## Playgama（尝试分销网络）

开发者入口：https://playgama.com/developers

- 关注统一 SDK 与第三方门户分发，但是 SDK 通用不等于平台愿意接受游戏，更不代表保证流量。
- **当前包没有接入 Playgama SDK**，不得假装是已完成的 Playgama 正式包。
- 需确认：合作渠道的实际名单和采用率、净收入定义、独家/非独家、撤回机制、网络 KPI 和不同渠道广告适配。
- 要求书面确认 Playgama 是否与 Coolmath 等授权方式冲突。

## Poki（仅在具备独家策略后考虑）

官方标准：https://developers.poki.com/guide/what-we-look-for

- 本作仍未证明足够原创性、艺术质量与长期游玩深度；不建议现在直接锁定网页独家。
- 在多平台分发或出售非独家许可之前确认 Poki 的许可边界，避免多地投递同一游戏形成合同冲突。

## 合同禁止默认同意的项目

- 永久/不可撤销/全球/可转授权/独家许可：必须拆分期限、地域、渠道、品类和撤销条件。
- 若要求交付源代码：应明确只交付具体游戏商业使用所需材料，而不是整个 AI 制造系统和无关模块库。
- 回收顺序：营销费、SDK 管理费、采购成本、支付手续费是否先回收；按毛收入还是净收入分成。
- 推荐承诺：宣传的“全网月度流量”不是你的作品获得的保底流量。
- AI/开源素材权利：生成过程、依赖、字体/音乐/图片许可都必须独立清点。

## 推荐的商务邮件材料清单

1. 30–60 秒有真实操作画面的短视频；2. 一句话核心玩法 + 有区别的相位机制；3. 试玩链接；4. 目标平台专用 HTML 包；5. QA 通过证据与手机录像；6. 权利声明；7. 独家/非独家许可偏好；8. 一份问询清单（采购价格、实际分发、商务联系人、审核周期、是否承诺初测流量）。

**禁止在没有书面确认的情况下，把同一游戏同时给予多个发行商排他谈判权。**
