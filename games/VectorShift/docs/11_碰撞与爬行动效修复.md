# 碰撞与爬行动效修复

日期：2026-10-22。针对用户报告“应该卡住却出去了、爬行不够丝滑”修复新密盘模式。

## 原因与修复

| 原因 | 现在的行为 |
| --- | --- |
| 射线遇到心形/叶形轮廓空格就结束，忽略凹口另一侧的身体 | 扫描到整个矩形棋盘边界，轮廓只决定布局，不作为穿越障碍的出口；同一条蛇的身体也会阻挡头部 |
| 动画开始即从规则状态删除，仍可见的身体不再阻挡下一条 | 尾巴完全离开画布后才提交移除；途中重复点击不会重复启动，撤销取消最近一次未结束的放行 |
| 两条静态都可走的蛇，出口射线可能在空白处相交 | 预约完整身体与出口路径，相交时等待前蛇离场，不相交时允许并行 |
| 长短蛇被压入近似固定的短时长，每帧重新生成曲面像素 | 按实际路程计算时长，110ms柔和加速后以25格/秒爬行；曲面纹理预先缓存，每帧更新路径裁切、圆尾、头部和投影 |

阻挡反馈为240ms平滑小幅回弹。等待运动中的前蛇不会计入失误；没有全盘动画锁。减少动态设置会立即完成已合法启动的放行。刷新时未完成的放行恢复为可见的蛇，保存记录中不存在提前消失的身体。通关发生在最后一条尾巴离场之后。

严格规则使旧心形的s07暴露出循环依赖。迁移保持全部盘面单元格与皮肤，只反转s07的头尾，重新计算见证与指标；五关仍可解。生成器与保存数据标记ruleVersion=2，提供`--repair-exits`确定性迁移。旧存档的操作历史会按现行规则重新验证，非法历史会安全重开该盘。

## 实际验证

- 规则测试28项通过：包括四向凹口、非连续轮廓、自体阻挡、旧非法历史拒绝、求解与撤销。
- 运动测试4项通过：相交路径预约、四向尾部离场、长短蛇同速与起步连续性、全部128条解题路径按2世界像素间距独立采样排查碰撞。
- 五关生成审计通过，重算几何、依赖、随机合法顺序和身体跟随。迁移只反转心形一条蛇。
- 浏览器基本回归13组通过：六视口、真实头部/身体点选、触摸缩放、并行与撤销、存档、英文渠道和SDK mock。
- 专项浏览器检查通过：凹口后的障碍、移动中继续阻挡、重复点击、两条可走但出口交叉、无关路径并行、运动中撤销与刷新、减少动态切换、通关等待尾巴。
- 在默认动画下真实点击五关全部128条蛇，全部完成，页面错误0。该检查并非用减少动态模式跳过动画。

专项报告与六个实际渲染帧保存在[artifacts/motion-fix/](../artifacts/motion-fix/)。本机无界面Chromium记录的rAF间隔中位16.7ms、各盘P95为16.7～16.8ms，只描述该环境调度情况，不证明物理手机帧率。移动端触摸与布局检查仍使用模拟，物理手机观感待验证。

[最新实录](../artifacts/dense-playthrough.webm)记录默认动画下完整首盘、心形前段与叶形选择。验收重点是凹口后的身体仍阻挡、前蛇尾巴离场前不穿越、头尾连续沿圆角前进且没有凭空截断。

## 复现

```powershell
node tests/dense-core.test.cjs
node tests/dense-motion.test.cjs
python src/dense-levels.py --verify
python src/build.py
node tests/dense-smoke.cjs
node tests/dense-collision-smoke.cjs
# 本地服务开启后
node tests/dense-capture.cjs
python src/package_delivery.py
```

浏览器脚本使用Playwright，可通过`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`指定本机运行时。专项脚本自带临时HTTP服务；录像可用`CAPTURE_URL`指定演示地址。
