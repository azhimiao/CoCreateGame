# PROMPT 03｜给独立审计 Agent（不可与施工作者同一角色）

审计范围：`games/{GAME_ID}/` 中完整 GDD 和数据，不要替作者重写设计。

输出按严重级别分组的 Findings。至少核查：

1. **市场事实**：最近榜单、老案例、发行商作品、正式购买意愿有没有偷换？出处能打开吗？
2. **游戏玩法**：按文档能从开始玩到结束吗？有隐藏未定义规则吗？首 30 秒和前五分钟到底发生什么？
3. **原创性**：和已知作品是否只是名称/素材/数值换皮？存在抄袭表达或资源权利风险吗？
4. **工程**：具体 schema、API、参数、状态机、输入、关卡、异常、资源足不足以独立施工？
5. **数值与关卡**：可解性、可达性、无限资源、死循环、过度重复、策略深度是否验证？
6. **用户体验**：易理解、误触、复玩、失败反馈、视觉一致性是否有证据？
7. **发行**：每个平台构建/SKD/广告/隐私/包体/独家是否可同时满足？
8. **商业**：广告 RPM、CPI、授权报价、成功率、平台流量有无编造？是否覆盖失败项目成本？
9. **知识产权**：开源许可证、素材权利和已有 IP 的重合如何处理？
10. **可证伪**：是否设计了即使游戏失败也能明确停止开发的标准？

每个 Finding 给出 `[BLOCKER|MAJOR|MINOR] 文件名:段落、证据、改法、验证方法`。

最终必须做出 **GO / REVISE / KILL**，允许淘汰。任何 BLOCKER 存在则不能 GO。不要把「可运行代码」当「具备市场竞争力」。
