# G02 完整游戏设计｜签章收纳台

版本1.1｜2026-10-21｜**本文件全为 HYPOTHESIS 产品定义，不是对标测量值**。唯一已测的是离线形式规则和20关解，见 verification。工作名未清商标。机制候选待独立审计和人类批准。

## 1. 玩家承诺、场景和目标

一张平整邮务工作台、四种无品牌邮片、一排封箱章。玩家先规划借位，逐件归类，再亲手封箱，观察新柜解锁。无角色故事任务或文字剧情；桌面邮务只是清晰的视觉语义。目标是在当前关把每种邮片全部封成一个包，台面清空。20关是完整首批合集，L20后允许重玩，无虚构后续内容。

## 2. 容器与物件

物件仅有 `A/B/C/D` 四种类型；同类外观完全相同，无隐藏特殊个体。A圆片、B菱片、C星片、D叶片，颜色+轮廓+字母同时区分。物件占1容量单位。需求量由每关 `demand[type]` 指定为2或3；初始全台该类型件数必须恰好等于需求，无生成/销毁来源。

2—6个托盘 `T0…`。每盘容量1—3；堆栈数组由底至顶，末项是唯一可取件。所有层始终可见；没有背面或遮挡随机信息。`sealable=false` 的浅盘仅能借位，即使凑齐也不能封箱。容量不等于需求：容量1浅盘永远无法容纳需求2/3，其他盘若长度未达到需求不能封。

托盘三种派生状态：OPEN、LOCKED、SEALED。SEALED优先于锁判定。LOCKED 内物件可见、不可作为源或目标，不可封；锁的 `unlock_after` 列出颜色章，全部已经封过才OPEN；空列表立即OPEN。只检查颜色是否封过，与在哪盘封无关。SEALED 不可再装物/出物/再封，也不腾成空位；动画后显示邮包卡，位置保留，防止布局跳动。

接收集合 `accepts` 为非空颜色集合。X2/X12 检查目标盘标签是否包含移动件类型；源盘只需可取件，不重新检查标签；初始数据也必须符合各盘接收集合。V0/X1所有盘接受本关全部类型。标签表示“允许接收”，不是不同颜色可混叠的许可。

## 3. 精确动作与优先级

`MOVE(src,dst)` 合法当且仅当：不同盘；两盘OPEN；源非空；目标未满；源顶部类型在目标接收集合；目标为空或目标顶部与源顶部同类。一次只取**一件**，即使连续同类也不整段搬运；无交换、跨层取件、自动归类或连锁。成功原子地源pop/目标push，记录一个撤销快照，动作数+1。非法输入不改变规则盘面/逻辑动作数/撤销历史，显示原因；首次有效身份拒绝仍按04消费协议序号、缓存失败和记录一次拒绝事件。

`SEAL(at)` 合法当且仅当：盘OPEN、允许封箱、非空、所有物件同类c、长度恰好等于 `demand[c]`。不要求长度等于盘容量。提交后清空该盘堆栈、标SEALED(c)，记录章c；本关该类型不可能再次出现。所有章条件重新计算，多个锁可同时打开。动作数+1。封箱是独立按钮，不会因最后一件移动到位而自动发生。

每次成功MOVE/SEAL后顺序：快照→逻辑原子提交→版本+1→守恒校验→解锁派生→先胜利→若未胜且合法MOVE/SEAL集合为空则DEADLOCK→持久化→视觉播放。胜利=`所有盘物件为空 AND 每个需求颜色恰好封过一次`，仅整理成同色未封箱不算胜。无状态随机性、无时间/步数上限。计时仅研究用，暂停/后台不计。

死局只定义为当前无合法前进动作且未胜利；有合法动作但数学无解可以继续试探，不能把循环或提示搜索超时说成失败。死局弹窗允许撤销/重开/关卡选择，无生命扣除。无限撤销指不消耗货币/次数；为内存持久化只保留最近128个前进状态，超出丢最老快照，UI明示“可回退最近128步”；最初状态总可重开。无Redo。

`UNDO` 在PLAY/DEADLOCK且历史非空可用，恢复封箱、全部物件及逻辑动作数；锁由恢复章重新派生，已开锁会重新锁。revision每次成功UNDO也+1；总操作流水序号仍递增，不能回滚分析记录。重载保留盘面/历史/revision但换新command_epoch、seq从1开始，旧epoch迟回无副作用，详见04。胜利结算阶段不能撤销，避免已完成进度重复奖；可重开同关。`RESTART` 需确认，复原本关初始状态和空历史，不消耗资源，不回滚已完成关卡。`HINT` 免费；精确搜索在500ms/20000状态的任一预算到达即终止为UNKNOWN，文案“暂未找到路线，可撤销或重开”，不得随便指一个假解。找到解只高亮首动作，不自动执行。开发实现须分帧/Worker，不能阻塞UI。离线全量BFS没有此实时预算，二者不可混淆。

## 4. 输入与反馈

触控：未选中时，点击OPEN且非空盘的顶部物件选源；已选中时，点击同源盘取消，点击任一其他盘（含其顶部、空白、锁盘或已封盘）一律先尝试MOVE。成功清空选择；失败显示原因并保留原源盘，不自动改选。换源必须先点同源或盘外空白取消，再点新源顶部。锁盘作为非法目标时显示缺少章且保留选择；未选中时点锁盘只显示缺章。拖动从未选中盘的顶部或已选源顶部开始，超过8 CSS px进入拖动；放到其他盘按上述规则提交，放到盘外/取消触摸回原位并清空选择。普通点击盘外空白取消选择。封箱按钮永远独立、优先于盘面命中；误点非就绪按钮显示原因，保留选择，封箱成功清空选择。

鼠标左键与触控同义，不依赖悬停。键盘Tab遍历盘/按钮；Enter选择或确认，Esc取消选择/开暂停，U撤销，H提示，R开重开确认；暂停/弹窗内快捷键不得穿透。只认第一个pointer，第二指忽略；系统中断取消尚未提交的拖动。逻辑提交在释放时一次发生，动画160ms期间新的棋盘命令返回BUSY且缓存、不排队；精确传输重试先按04去重返回原receipt，不能重判BUSY，暂停操作可即时收尾动画而保留提交状态。

PLAY统一三列两行/小横屏六列一行无滚动（06），320×568含安全区与font1.3仍显示6盘和全部核心按钮。GAME手势只拖顶件不转滚动；其它菜单滚区>8CSSpx由SCROLL持有、取消tap，边缘不滚棋盘、不发MOVE。旋转/弹窗/系统cancel清选择，固定按钮由BUTTON持有且移出取消；完整所有权表在04/06，三处同义。

选中描边、合法目标底环；非法震动/轻提示音可关闭；封箱240ms纸带合拢，解锁180ms锁章点亮。减少动态模式将位移/缩放动画置0ms，仍有静态颜色/文字反馈。音频只在用户首次交互后启用，失焦暂停，回来需手势时显示静音图标，不影响规则。

## 6. 可分离机制实验

V0：所有盘立即开放、全色接收；仍保留主动封箱和托盘退出，作为共同基线。X1：仅启用章锁，接收全色。X2：仅启用接收标签，所有盘开放。X12：二者同时启用，不纳入初次单因子因果判断。四者是同一G02候选的实验配置，不新增项目ID。

X1相对V0固定布局/需求/美术，仅把`unlock_after`从空设为关数据值；X2相对V0仅缩小`accepts`。离线验证同一初态的合法动作确实改变且消融基线有解，证明可分离而非换皮，不证明体验提升。默认20关教学顺序不是随机实验；正式盲测用第12份成组方案。
