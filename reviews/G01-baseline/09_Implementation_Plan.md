# G01 可执行任务DAG与交付闸门

全部未来开发任务为 **NOT_STARTED**；本轮只完成准备数据/文档/离线验证。`tasks.json` 是任务执行权威，每项包含role、前置、输入、输出、写入目录、DoD与验证方法。本章不能被理解为已经获准运行T03以后的任务。

## DAG

```mermaid
flowchart LR
 T01[独立审计] --> T02[人类批准G01与版本]
 T02 --> T03[锁版与许可]
 T02 --> T05[原创资产]
 T03 --> T04[规则与测试向量]
 T04 --> T06[UI]
 T05 --> T06
 T04 --> T07[存档恢复]
 T06 --> T08[20关集成]
 T07 --> T08
 T08 --> T09[浏览器真机QA]
 T09 --> T10[盲测消融]
 T10 --> T11[合同权利核验]
 T11 --> T12[P02 Basic]
 T11 --> T13[P04 Bridge]
 T11 --> T14[P05兼容试包或停止]
```

T12/13/14也直接依赖T09，避免合同审查替代技术QA。各分支某个渠道停止时必须提交有原因的停止报告而不是假通过，T15只覆盖正式决定继续的渠道；Full分支T16不阻断Basic可评审资料，但必须等正式Full邀请，当前没有邀请。

## 本轮可复验与未来命令

在G01目录运行：

```powershell
python tools/validate.py
python tools/write_level_catalog.py
python tools/package.py
```

依赖在`tools/requirements-validation.txt`记录本轮jsonschema版本。`prepare_data.py`是数据编辑源，可重生成spec/tasks/schema，但修改后必须重新验证、生成05、审查差异和重打ZIP，不能只改MD。

未来npm命令尚未建立：`test:rules`/`test:save`/`test:ui`/`test:campaign`/`test:web`；渠道`build:p02-basic`/`build:p02-full`/`build:p04`；P05按确认SDK单独定义。任务负责建立并记录真实执行结果，不在本轮用空脚本假绿。

## 并行与变更控制

只写本目录。T04/T07/T05分属future/rules、future/save、future/assets，不互相覆盖；T06/T08的场景合并由内容集成负责人串行处理。通用模块只写提案待主控审查，不改root STATUS/shared/data。每次规则变化升级spec_version、重新跑schema/几何/解/全可达、更新对应文档和hash；独立审计结论对旧版本失效时重新审计。工期与人日尚未测定，不报“某日必交付”。
