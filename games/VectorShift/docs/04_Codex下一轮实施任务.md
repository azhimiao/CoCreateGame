# 04｜交给 Codex 的下一轮工程任务书

你正在接手 `Vector Shift V0.2` 独立游戏项目，请先读 `README.md`、`docs/01_机制与对标边界.md`、`docs/03_玩家测试及证伪方案.md` 和 `src/game-core.js`。

## 硬性要求

1. 保留原先所有20关的可解性；修改规则后须重新生成并运行 `node tests/core.test.cjs`。
2. 所有新画面必须和纯机制核心解耦。不得用图像动画决定碰撞结果。
3. 不复制 Arrow Puzzle、Arrow Escape 或任何竞品美术、关卡数据、源码、商标；相似品类仅作公开对标。
4. 不默认接入第三方广告、统计和用户标识。平台 SDK 必须分构建适配，并明确许可与隐私规则。
5. 单次迭代最多只改变一个待检验变量，并清楚记录用户指标，不要为了增加功能而堆砌系统。

## 建议任务顺序

Gate 1｜真人试玩准备：提供手机可访问的测试地址、受试者指引与可导出的事件 JSON；录屏由玩家自愿完成；确保直接跳关调试只在开发包有效。

Gate 2｜关卡质量：为每关记录有效动作数、首次可移除数、最短相位次数、玩家实际完成时长、提示使用情况；据此重排关卡；不要把 BFS 状态数量直接当真人难度。

Gate 3｜A/B 对照：基于现有引擎生成不含相位的独立试玩版，保证美术/提示/难度被控制，固定随机分流方案。首要比较相位规则是否真正增加主动继续率。

Gate 4｜商业候选版：只在用户数据足够好时打磨音效、过关节奏、无障碍、真机性能、英文文案、版权声明；为 Coolmath 和 CrazyGames 构建独立提交包。

Gate 5｜商业验证：获取渠道准入/初测流量的确认；非独家授权、分销与排他合作分开询价，统计真实每款渠道收益。

## 验收时输出

- 一份改动前后对照（规则、性能、可玩性和用户证据）。
- 测试日志、截图、20关求解通过结果。
- 待平台官方确认清单：SDK、广告、截图、内容政策、合同、统计和支付资格。
- 最后作出 GO / REVISE / STOP 决策，不得只写“建议继续优化”。
